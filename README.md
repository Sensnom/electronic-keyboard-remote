# Electronic Keyboard Remote

电子琴手机控制网页，包含曲目上传、演奏参数和信号日志三个页面。手机在本地读取MIDI，通过用户配置的WSS连接发送曲目和设置。

## 使用

1. 打开网页，连接设置已预填；可以直接连接并检查乐器，也可以修改地址、上下行主题及可选账号。
2. 在曲目上传页选择MIDI文件、练习轨道和速度，等乐器确认上传完成。
3. 在演奏参数页调整音量、音色、和弦、移调、八度、滑音和效果。切页不自动读取整组参数；固件支持时，可点击读取乐器设置同步当前值。首次读取前，控件显示网页初始值；之后保留已读取或乐器确认的值。可用项目取决于乐器固件，设置以乐器回传值为准。
4. 在信号日志页查看通信记录并导出。数字路径计时仅在设备提供相应能力时开放；未支持时不会显示测量值。
5. 三页之间通过站内按钮切换，保留当前连接、文件和正在进行的上传。按钮在网页初始化完成后开放，切换界面不会加载新文档；浏览器前进、后退也保留当前会话。刷新页面后需重新连接和选择文件。

默认WSS地址为`wss://broker.emqx.io:8084/mqtt`，设备上行主题为`tof/flowmeter/data`，设备下行主题为`tof/flowmeter/down`，QoS为0，账号密码留空。所有连接字段均可修改。

首次打开网页需手动连接。点击后，在当前网页会话内自动检查乐器应答；FPGA/联网模块重启或网络中断后自动恢复。手动断开会停止检查和重连。刷新或重新打开网页仍需手动连接，不保存密码或原始文件。

前台空闲时每5秒尝试检查状态，单次状态请求等待2秒、最多发送2次；上传、读取设置、测量或其他命令执行时不插入检查。检查连续两次状态以避开缓存应答并同步序号，只有乐器返回有效状态才显示已连接。网络恢复或返回网页时也会尝试检查。恢复不会自动重传中断的曲目或重新执行Loop操作。

当前同一台琴仍按单手机控制使用。两台手机轮流使用时，上一台先点断开，停止其自动探测，避免共享命令序号和应答互相干扰。使用自己的设备主题与受控账号。后台或锁屏可能中断上传，上传完成前请保持页面在前台。

## 部署

所有资源使用相对路径，可在GitHub Pages项目子路径部署。仓库根目录含index.html、parameters.html与logs.html，Settings → Pages选择main / (root)。不需要额外Node网页后端，仍需可供手机和乐器访问的MQTT服务，GitHub Pages不承担Broker功能。

MQTT.js浏览器包随网页提供，页面不依赖第三方CDN。连接地址需为浏览器信任证书的wss://入口。设备接线、供电和通信配置请按自己的硬件说明操作。

## 开发与验证

```sh
npm ci
npm test
```

测试需要Node.js、OpenSSL和Mosquitto，覆盖MIDI编译、二进制消息收发、应答与重试、参数范围和固件能力兼容。联网测试仅连接本机模拟设备。

浏览器回归另需 Python 3 和 Playwright Chromium。首次运行先安装浏览器，再执行测试。

```sh
npx playwright install chromium
npm run test:browser
```

浏览器测试以手机尺寸运行实际网页和通信模块，替换 MQTT 连接端，不接触实物设备。覆盖初始化期间的导航保护、连续切页、前进后退、上传与文件保留，以及弯音归零；实物网络稳定性仍需在手机与 FPGA 上确认。

更新浏览器依赖包时运行npm run vendor。不要上传账号、个人MIDI或其他私有文件。第三方组件的许可证随vendor目录提供；本项目网页源码尚未另行声明开放许可。
